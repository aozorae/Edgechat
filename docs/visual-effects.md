# 网页低特效与性能验证

个人设置中的“低特效模式”立即生效，仅保存在当前浏览器的 `edgechat.lowEffects`，不请求服务端、不改变其他用户。系统要求减少动态效果或透明度时自动启用，手动取消不能覆盖系统无障碍偏好。清除浏览器站点数据会移除手动选择。

低特效关闭背景模糊光团、玻璃高光和所有 `backdrop-filter`，缩短页面进出场效果；消息、附件、录音、加载状态与站点配色保持原有功能。未改动 Android 工程。

## 监听器生命周期

`liquid-glass.ts` 只注册一组 document 指针委托，动态节点不再触发 MutationObserver 全页扫描，也不逐个绑定匿名回调。命中元素及匹配的祖先每个动画帧最多更新一次位置，先读取布局再写样式。无精确悬停能力、页面隐藏或低特效开启时停止跟踪，卸载时清理监听与待执行帧。

保留原有 `.ui-surface`、`.chat-bubble`、`.liquid-glass-panel` 范围，不为新的消息组件额外引入视觉效果。当前消息组件使用 `.message-bubble`，所以旧选择器的重复绑定不能直接等同于所有消息行都受影响。

## 性能边界

大范围 `backdrop-filter` 可能增加背景采样和合成成本；叠加面板、模糊半径、背后持续运动的内容及浏览器 GPU 路径都会影响结果。CSS 变换动画不等于没有 GPU 或内存成本。低特效提供可控退路，不根据机型或屏宽猜测性能等级。

本轮 Chromium 定向验证重复初始化 100 次、分批新增 1000 个匹配节点后，监听器总数未增长；设置页背景滤镜从 2 处变为 0 处。移动尺寸视口及桌面布局均完成检查，但这不是实际手机端到端测试。

后续真实设备验证应使用同一账号、消息量、背景和滚动路径，对照完整特效与低特效，分别记录：

- 桌面与实际中低端手机的浏览器、系统版本、屏幕刷新率和温度状态。
- Performance 的主线程长任务、样式/布局/绘制时间及丢帧，配合 Rendering 的重绘和合成层观察。
- 空闲背景、持续滚动、连续收消息、弹层打开，以及页面切后台后的行为。
- DOM 增长前后的监听器与堆内存；先区分 Vue 业务监听器和玻璃特效监听器。

每种模式重复多轮，不以单次短录制、桌面 CPU 限速或模拟移动视口推断真实手机耗电和 p50/p95。人工或合成测试数据不得发送到生产群聊。
