# Security Policy / 安全政策

## Reporting a Vulnerability / 漏洞报告

Thank you for helping improve the security of this project.

If you discover a potential security vulnerability, **please report it privately instead of opening a public GitHub Issue or Pull Request.**

**How to report:**

1. Open the repository's **Security** tab.
2. Navigate to **Advisories**.
3. Click **Report a vulnerability**.
4. Submit the vulnerability details privately.

Please include the affected version, vulnerability description, reproduction steps, potential impact, and any relevant proof of concept.

感谢您帮助改进本项目的安全性。

如果您发现潜在安全漏洞，**请勿通过公开 GitHub Issue、Pull Request 或 Discussion 披露漏洞细节。**

**正确的报告方式：**

1. 进入仓库的 **Security（安全）** 页面。
2. 打开 **Advisories（安全公告）**。
3. 点击 **Report a vulnerability（报告漏洞）**。
4. 私下提交漏洞报告。

建议包含受影响版本、漏洞描述、复现步骤、潜在影响及相关验证材料。

## Responsible Disclosure / 负责任的漏洞披露

We ask security researchers to:

- Report vulnerabilities privately.
- Avoid public disclosure before a fix is available and disclosure has been coordinated.
- Avoid accessing, modifying, or disclosing other users' data.
- Refrain from destructive testing or disrupting production services.
- Give maintainers a reasonable opportunity to investigate and address the issue.

我们希望安全研究人员：

- 优先通过私密渠道提交漏洞。
- 在修复版本发布并协调披露前，避免公开漏洞细节。
- 不访问、修改或泄露其他用户的数据。
- 不进行破坏性测试或影响生产服务正常运行。
- 给予维护者合理的调查及修复时间。

## Response and Remediation / 响应与修复

- We aim to acknowledge valid reports within **7 days**, although response times may vary.
- Reports will be assessed based on severity, impact, and reproducibility.
- Confirmed vulnerabilities will be prioritized for remediation.
- We will coordinate disclosure with the reporter, generally after a security fix is available.
- Security advisories may be published to inform users about affected versions, mitigations, and available fixes.

- 我们争取在 **7 天内**确认收到报告，但实际响应时间可能有所变化。
- 将根据漏洞严重性、影响范围及可复现性进行评估。
- 对确认存在的漏洞优先安排修复。
- 原则上在安全修复版本可用后，与报告者协调公开披露。
- 必要时发布安全公告，说明受影响版本、缓解措施及修复方式。

## Supported Versions / 支持版本

Security fixes generally target the latest maintained release. Older versions may not receive individual security patches.

安全修复原则上针对最新维护版本。旧版本不保证单独提供安全补丁。

Users are strongly encouraged to keep their deployments updated.

强烈建议用户及时更新至最新安全版本。

## Security Research Recognition / 安全研究者致谢

We appreciate responsible security disclosures. With the reporter's consent, contributors may be credited in security advisories or release notes.

我们感谢负责任的安全漏洞报告。经报告者同意，可以在安全公告或更新日志中予以致谢。

This project does not currently operate a paid bug bounty program.

本项目目前不提供有偿漏洞奖励计划。
